# ai-chat

## What it does

Implements the third editor tab (AI chat): a single tool-calling LLM agent (`CvAgent` in [`assets/js/ai/langchain.js`](../../assets/js/ai/langchain.js)) that chats, builds a CV from scratch, edits an existing CV, or restyles it, coordinated by a UI layer ([`assets/js/ai/ui.js`](../../assets/js/ai/ui.js)) and persisted to IndexedDB via Dexie ([`assets/js/db/db.js`](../../assets/js/db/db.js)). One model with one bound tool set drives every turn — there is no intent classifier and no per-intent handler methods; the system prompt ([`assets/js/ai/prompts.js`](../../assets/js/ai/prompts.js)) tells the model when to use which tool. Four providers are supported: `openai`, `anthropic`, `google-genai`, and `fireworks` (OpenAI-compatible endpoint, reuses the `ChatOpenAI` adapter with a base-URL override).

## CLI code

- [`assets/js/ai/langchain.js`](../../assets/js/ai/langchain.js) (1129 lines) — `CvAgent` class, the whole agent. `configure(settings)` builds a `#routerModel` (cheap) and `#generatorModel` (reasoning) via `loadProvider()`/`PROVIDER_FACTORY` (lazy CDN import, cached per provider), applies provider-specific quirks (see Conventions), then binds the single `ALL_TOOLS` array to `#toolModel` via `bindTools()` — no per-intent tool subsets. `#buildBaseConfig(provider, apiKey)` returns provider-specific constructor options, including the Fireworks base-URL/custom-fetch override. `#executeTool(toolCall, opts)` is the tool-dispatch switch for all of `AGENT_TOOLS`/`GENERATION_TOOLS`/`CV_EDIT_TOOLS`; the `edit_cv` and `edit_styles` cases contain no inner model call — the tool call's own arguments are validated (Zod, `EditCvSchema`) and either routed through `#requestApproval` (edit_cv) or stashed as `#pendingStyle` (edit_styles). `#requestApproval(change, signal)` emits `ai:approval-request` and resolves with `{accepted, cvData}` once the UI responds. `#streamWithTools()` drives the token/tool-call streaming loop, bounded by `MAX_TOOL_ROUNDS = 12` (LLM round trips) and `MAX_TOOL_CALLS = 24` (total tool executions per turn, the real runaway backstop). `processMessage()` is the single public streaming entry point — no intent dispatch, just one call into `#streamWithTools` followed by assembling any accumulated from-scratch CV (`#generationAccumulator`) and any pending style change (`#pendingStyle`) as trailing `cv_data`/`css_update` events. `#buildSystemPrompt(basePrompt)` prepends context layers (see Conventions for the actual final order). `summarize()`, `summarizeDocument()`, `summarizeImage()` are router-model-only helper calls unrelated to the tool loop. `toLangChainMessages()` and `formatUserContent()` are module-level (not class) helpers for message-format conversion.
- [`assets/js/ai/ui.js`](../../assets/js/ai/ui.js) (1409 lines) — chat UI coordinator. Owns settings/chat screen switching (`showSettings`, `showChat`, `getCurrentAiScreen`), the send-message flow (`handleSendMessage`), and the streamed-token rendering path: `appendToken` feeds each token into `renderStreamMarkdown` (the only throttled one of the three — see Conventions), `flushRemainingTokens` does one final unthrottled paint at stream end, and `paintStreamedContent` is the shared DOM-painter both call into. Registers the `ai:approval-request` and `ai:clarification-request` listeners per message send and tears them down after the stream ends. `applyCvFromAI(cvData, path, operation)` (exported, also reachable via `window.applyCvFromAI` set up in `main.js`) applies a full or partial CV update to localStorage/DOM and returns the resulting CV data. `currentValueAtPath(path)` reads the "before" side of an approval diff from the currently saved CV. `formatApiError(err)` translates HTTP-status substrings (529/401/403/404/429/500/502/503, timeout, network) into user-facing messages. `initializeAI(container)` (exported, lazy-loaded by `editor.js`/`main.js`) is the module's entry point. `validateApiKey(provider, apiKey, model)` pings each provider's API directly to verify a Settings key, including a `fireworks` validator against `https://api.fireworks.ai/inference/v1/models`.
- [`assets/js/ai/schemas.js`](../../assets/js/ai/schemas.js) (25 lines) — re-exports `CVDataSchema`/`PersonalSchema`/`SectionItemSchema`/`SectionSchema`/`LinkSchema` from `../validation.js` (cv-data domain); defines `AiPartialUpdateSchema` (`operation: 'set'|'insert'|'delete'`, dot-notation `path`, `data` union of `PersonalSchema`/`SectionSchema`/`SectionItemSchema`/arrays thereof/string/null) — this is the schema `edit_cv`'s tool arguments are validated against.
- [`assets/js/ai/prompts.js`](../../assets/js/ai/prompts.js) (93 lines) — `DATE_CONTEXT` (ISO date string), `AGENT_SYSTEM_PROMPT` (the single system prompt covering chat/build/edit/restyle/research/ask/remember, plus operation-choice rules for `edit_cv` and a CV-writing-best-practices block), `SUMMARIZATION_PROMPT`; `buildSummaryPrefix()` helper.
- [`assets/js/ai/search.js`](../../assets/js/ai/search.js) (190 lines) — `configureSearch(settings)`, `isSearchConfigured()`/`isTavilyConfigured()`; `webSearch(query, opts)` (Brave Search API); `tavilySearch`, `tavilyExtract`, `tavilyCrawl`, `tavilyMap` (Tavily API wrappers, used by the `tavily_*` agent tools).

## Conventions worth knowing

- **Edits are gated by human approval, not a second tool call.** `edit_cv`'s arguments (`operation`/`path`/`data`, plus a `summary` for the approval UI — `EditCvSchema`, `assets/js/ai/langchain.js:199-201`) ARE the change; there is no inner model that generates it and no `accept_*` tool. In `#executeTool`'s `edit_cv` case (lines 585-614), the change is Zod-validated first (line 591 — the provider does not enforce tool-arg shape when constrained generation is disabled, e.g. Fireworks with `disable_grammar`), then `#requestApproval()` (lines 740-757) emits `ai:approval-request` and blocks on the UI's decision. In `ui.js`, the `ai:approval-request` listener (lines 494-527) renders `approvalDialog()` as a full-viewport modal on `document.body`, applies the change via `applyCvFromAI()` on accept, and calls `respond(accepted, cvData)` — the applied CV is handed back so `#editorContext` is refreshed for the next edit in the same turn (`langchain.js:604-610`). `edit_styles` follows the same shape: its arguments are the complete CSS (`langchain.js:616-622`), stashed as `#pendingStyle` and yielded as a `css_update` event after the stream; the user applies it via `cssPreviewCard()`'s "Apply Styles" button, no accept step. From-scratch generation still goes through the `set_personal_info`/`set_summary`/`add_section` accumulator tools (`GENERATION_TOOLS`, lines 177-195) into `#generationAccumulator`, assembled into one `cv_data` event and shown as a preview card.
- **Fireworks reuses the OpenAI adapter.** `CDN.fireworks` points at the same `@langchain/openai` module as `CDN.openai` (`langchain.js:20-28`); `loadProvider()` maps both to `mod.ChatOpenAI`. `#buildBaseConfig` sets `configuration.baseURL` to `FIREWORKS_BASE_URL` (`https://api.fireworks.ai/inference/v1`, line 32) plus a custom `fetch: stripStainlessFetch` (lines 39-45): the OpenAI SDK adds `x-stainless-*` telemetry headers that Fireworks' CORS policy doesn't allow, which fails the browser preflight, so `stripStainlessFetch` strips those headers before every request. `configure()` also passes `modelKwargs: { disable_grammar: true }` for Fireworks (lines 420-424): Fireworks' constrained-generation grammar builder fails on this app's deep union/optional Zod schemas ("Failed to build a constrained-generation grammar"), so grammar enforcement is disabled and the resulting tool-call JSON is validated with Zod instead (this is what makes the `edit_cv` Zod-validate-and-retry path load-bearing, not just defensive). `templates.js`'s `PROVIDERS` entry for `fireworks` (lines 25-34) notes both configured models must support tool calling.
- **Known LangChain quirks actually present in this code:**
  - Anthropic's LangChain adapter defaults `topP`/`topK` to `-1`, which the API rejects; both are explicitly set to `undefined` post-construction for the Anthropic provider (`langchain.js:448-454`).
  - OpenAI reasoning models only accept `temperature: 1`, so the `temperature` override is skipped entirely for `provider === 'openai'` (`skipTemp`, lines 417-418, 429, 443); OpenAI also rejects `max_tokens`, so `modelKwargs: { max_completion_tokens: 16_384 }` is used instead of `maxTokens` for OpenAI specifically (lines 433-438).
  - Anthropic requires strictly alternating user/assistant messages; `toLangChainMessages()` merges consecutive same-role history entries with a newline join (lines 322-344) and also filters out messages with empty/whitespace-only content (line 330).
  - `formatUserContent()` guards against Anthropic rejecting empty multipart content arrays by pushing a placeholder text block if attachments+text would otherwise produce zero parts (lines 314-317).
  - Note: this repo's root [`CLAUDE.md`](../../CLAUDE.md) also documents a `withStructuredOutput`/`response.raw.tool_calls[0].args` fallback quirk — that pattern is not present anywhere in the current [`assets/js/ai/`](../../assets/js/ai) source (verified by search); it belonged to the now-removed intent-classifier code path.
- **`#buildSystemPrompt` context order is inverted from source order** (`langchain.js:513-537`). The method builds the string by successively prepending, so reading the final prompt top to bottom: `DATE_CONTEXT`, then `[Previous conversation context]` (`#summary`), then `[User Documents]` (`#documentSummaries`), then `[Learned Facts]` (`#learnedFacts`), then `[User Profile]` (`#userProfile`), then the base agent prompt last. Adding a new block near the top of the method's source puts it near the bottom of the assembled prompt.
- **Streaming render is throttled and buffer-size-gated to avoid an O(n²) freeze** (`ui.js:42-95`). `renderStreamMarkdown` is `throttle()`d to a 150ms interval and skips repaint if no new tokens arrived since the last paint (`lastRenderedLen` check). Buffers above `STREAM_MARKDOWN_MAX` (20,000 chars) are painted as escaped plain text instead of running the full markdown-it pass on every tick; buffers above `FLUSH_MARKDOWN_MAX` (200,000 chars) stay plain text even at the final flush. `paintStreamedContent()` preserves any already-injected `.ai-gen-step`/`.ai-cv-preview`/`.ai-approval-record` child elements across a mid-stream repaint so accept/reject history and generation-step cards aren't wiped.
- `save_user_fact` runs a one-word ("SAVE"/"SKIP") router-model classification (plain `invoke`, not structured output) against existing profile + learned facts before pushing to `#learnedFacts` and calling `#factSaver` (`langchain.js:673-698`) — facts judged redundant are silently skipped, not saved.
- `ask_clarification` returns a `Promise` that resolves via the `respond` callback emitted on `ai:clarification-request`; if the passed `AbortSignal` fires first, the promise rejects with `DOMException('Aborted', 'AbortError')` (`langchain.js:709-723`).
- `#executeTool`'s `web_fetch`, `tavily_extract`, `tavily_crawl`, and `read_document` results are hard-truncated (15,000 or 30,000 chars) with a `[Truncated]` suffix to bound context size.
- The agent loop has two independent caps: `MAX_TOOL_ROUNDS = 12` (LLM round trips per turn) and `MAX_TOOL_CALLS = 24` (total tool executions per turn, checked per individual tool call) — the latter exists because a single round can contain many tool calls, so round count alone doesn't bound total tool executions (`langchain.js:249-256`, `842-848`).
- `formatApiError()` in `ui.js` matches on substrings of `err.message` (not status codes from a structured error object), so it depends on the underlying HTTP client/provider SDK including the numeric status in the thrown error's message text.
- Chat titles are now set deterministically from the first user message (date prefix + truncated text, `ui.js` in the `'done'` case), not via an extra LLM call — there is no title-generation model call anywhere in this domain.
