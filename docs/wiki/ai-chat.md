# ai-chat

## What it does

Implements the third editor tab (AI chat) that can read/generate/modify CV data and CSS through a tool-calling LLM agent (`CvAgent` in [`assets/js/ai/langchain.js`](../../assets/js/ai/langchain.js)), coordinated by a UI layer ([`assets/js/ai/ui.js`](../../assets/js/ai/ui.js)) and persisted to IndexedDB via Dexie ([`assets/js/db/db.js`](../../assets/js/db/db.js)). Every user message is classified into one of five intents (`chitchat`, `clarification`, `full_generation`, `partial_update`, `style_update`) before being routed to a handler.

## Conventions worth knowing

- `#buildSystemPrompt()` in [`assets/js/ai/langchain.js`](../../assets/js/ai/langchain.js) (lines ~507-527) prepends context blocks in this actual order, outermost (top of the final string) to innermost: `DATE_CONTEXT`, then `[Previous conversation context]` (`#summary`), then `[User Documents]` (`#documentSummaries`), then `[Learned Facts]` (`#learnedFacts`), then `[User Profile]` (`#userProfile`), then the handler's `basePrompt` last. Each conditional block is built by prepending to the running `prompt` string, so the last block applied (`userProfile`) ends up closest to `basePrompt` and the first-applied block (`summary`) ends up right after the date.
- The propose/accept pattern: `generate_partial_update`/`generate_style_update` tool calls make an inner `withStructuredOutput` call to `#routerModel`, store the result in `#proposalMap` keyed by a `crypto.randomUUID()`, and return a text summary to the outer model; `accept_partial_update`/`accept_style_update` move the proposal from `#proposalMap` into `#pendingChanges` and delete it from the map. `#pendingChanges` is what `processMessage()` yields as `cv_section`/`css_update` events after streaming completes.
- `save_user_fact` runs a one-word ("SAVE"/"SKIP") router-model classification against existing profile + learned facts before pushing to `#learnedFacts` and calling `#factSaver` — facts judged redundant are silently skipped, not saved.
- `ask_clarification` returns a `Promise` that resolves via the `respond` callback emitted on `ai:clarification-request`; if the passed `AbortSignal` fires first, the promise rejects with `DOMException('Aborted', 'AbortError')`.
- `#executeTool`'s `tavily_extract`/`tavily_crawl`/`read_document` results are hard-truncated (15,000 or 30,000 chars) with a `[Truncated]` suffix to bound context size.
- Anthropic's LangChain adapter has `topP`/`topK` explicitly set to `undefined` post-construction (its default of `-1` is rejected by the API); OpenAI models use `modelKwargs: { max_completion_tokens: 16_384 }` instead of `maxTokens` and skip the `temperature` override entirely (reasoning models only accept `temperature: 1`).
- `formatApiError()` in `ui.js` matches on substrings of `err.message` (not status codes from a structured error object), so it depends on the underlying HTTP client/provider SDK including the numeric status in the thrown error's message text.
