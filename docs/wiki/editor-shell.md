# editor-shell

## What it does

Bootstraps the app ([`assets/js/main.js`](../../assets/js/main.js)), manages the Monaco editor instance and its JavaScript/CSS/AI mode switching ([`assets/js/editor.js`](../../assets/js/editor.js)), and provides the surrounding UI chrome: resizable split-pane layout, floating action menu, help/prompt/privacy modals, toast notifications, keyboard shortcuts, and fullscreen toggling. All modules communicate through a shared global event bus ([`assets/js/observable.js`](../../assets/js/observable.js)) rather than direct function calls between unrelated modules, per the `on`/`emit` pattern.

## CLI code

- [`assets/js/main.js`](../../assets/js/main.js) — entry point; the async IIFE runs init order: `loadAndApplyStyles()` → `initializeEditor()` → `renderCV()` → `initializeActionMenu()` → `initializeKeyboardShortcuts()` → `initializeModal()` → `initializeSplitPane()` → `restoreEditorPaneState()` → `initializeToasts()`; shows the help modal on first visit (`isFirstVisit()`/`markVisited()`); exposes handler functions on `window` for inline `onclick` attributes in [`index.html`](../../index.html); lazy-imports `./ai/ui.js` for `window.applyCvFromAI`; subscribes to `ai:cv-applied` to re-render the CV
- [`assets/js/editor.js`](../../assets/js/editor.js) — owns the Monaco editor instance (`getEditor()`, `getEditorMode()`); `initializeEditor()` configures the Monaco AMD loader against the `monaco-editor@0.52.2` CDN path, resolves initial content (draft → CSS mode → code/result consistency check → default), and lazy-loads `./ai/ui.js` when starting in `ai` mode; `setEditorMode(mode)` switches between `javascript`/`css`/`ai`, saving/restoring drafts and cursor position per mode; `applyChanges()` evaluates JS via `new Function(code)`, validates with `CVDataSchema`, and calls `renderCV()`, or applies CSS via `applyStyles()`; `resetData()` confirms via `window.confirm()` before clearing saved data/styles; auto-saves a debounced (500ms) draft on every Monaco content change
- [`assets/js/split-pane.js`](../../assets/js/split-pane.js) — `initializeSplitPane()` wires mouse/touch drag handlers on `#divider` to resize `#cvPane`/`#editorPane` (desktop only, disabled ≤768px viewport width, minimum 300px per pane); persists the left-pane percentage to `localStorage` key `cv-split-pane-widths`; `toggleEditorPane()`/`isEditorPaneOpen()` handle the mobile-only open/close toggle (`localStorage` key `cv-editor-pane-open`); `restoreEditorPaneState()` re-applies saved widths (desktop) or open state (mobile) on load
- [`assets/js/keyboard.js`](../../assets/js/keyboard.js) — `initializeKeyboardShortcuts()` binds a single `keydown` listener that emits observable events for each shortcut: `⌘S`/`Ctrl+S` → `editor:save` + `chat:save-settings`, `⌘Enter` → `chat:send`, `⌘E` → `editor:mobile-toggle`, `⌘P` → `cv:print`, `⌘\` → `editor:full-screen`, `⌘,` → `chat:go-to-settings` (guarded by a double-press-within-1000ms check via `checkTimesPressed`), `Escape` → `escape` (+ `menu:close` if the action menu is open), `?` → `page:help` (only when not focused in an `INPUT`/`TEXTAREA`/`SELECT` and not editor-focused); a second `Escape` within `KEYPRESS_INTERVAL` (500ms) triggers `escape:double`, which aborts the AI chat stream (`chat:abort`) if in AI chat screen, otherwise closes the editor pane; imports `getCurrentAiScreen` from [`assets/js/ai/ui.js`](../../assets/js/ai/ui.js) (ai-chat domain) to gate several handlers
- [`assets/js/action-menu.js`](../../assets/js/action-menu.js) — `toggleActionMenu()` toggles the `.show` class on `#actionMenu`; `openEditor()` closes the menu and opens the editor pane via `editor.js`'s `toggleEditor()`; `printCV()` closes the menu, emits `cv:print`, and calls `window.print()`; `initializeActionMenu()` closes the menu on outside click
- [`assets/js/modal.js`](../../assets/js/modal.js) — `initializeModal()` wires backdrop-click and `cancel` event close handlers on `#helpModal`; `showModal(markdownUrl, title)` fetches a markdown file, renders it with `renderDocMarkdown()` (from [`assets/js/markdown.js`](../../assets/js/markdown.js)), caches the rendered HTML and raw text in module-level `Map`s (`wasFetched`, `markdownCache`) keyed by URL; `showHelpModal()`/`showPromptModal()`/`showPrivacyModal()` load [`readme.md`](../../readme.md)/[`prompt.md`](../../prompt.md)/[`privacy.md`](../../privacy.md) respectively (fetched from the repo root at runtime); `isFirstVisit()`/`markVisited()` use `localStorage` key `cv-first-visit`; `copyModalMarkdown()` copies the cached raw markdown to the clipboard via `navigator.clipboard.writeText()` with a temporary check-icon swap for feedback
- [`assets/js/toast.js`](../../assets/js/toast.js) — `initializeToasts()` looks up `.toasts` container; `notify(message, optionsOrType)` accepts either a type string or an options object (`{ type, timeout, dismissable }`, defaults `info`/5000ms/dismissable), renders `message` through `parseMarkdown()`, and auto-dismisses after `timeout` ms (300ms fade via `dismissToast`); module-level `on(...)` subscriptions call `notify()` for `cv:save`, `cv:reset`, `cv:import`, `cv:export`, any event matching regex `/error/`, `ai:cv-applied`, and `ai:settings-saved`
- [`assets/js/ui-utils.js`](../../assets/js/ui-utils.js) — `toggleFullscreen()` inspects whether the Monaco editor container has DOM focus to decide whether to fullscreen the editor pane (`.fullscreen` class) or the CV pane (`.fullscreen-cv` class) on `.split-view-container`; toggles the FAB fullscreen icon between `fa-expand`/`fa-compress`; emits `editor:fullscreen` with `{ pane, isFullscreen }`
- [`assets/js/observable.js`](../../assets/js/observable.js) — lazily constructs a single global `ObserverEngine` (from `window.LogosDx.Observer`, CDN-loaded) with a `spy` hook that forwards every `emit` call to Google Analytics (`window.gtag`) as event `event_category: 'cv-generator'`; exports `emit`/`on`/`once`/`off`; `emit()` always stamps `timestamp: new Date().toISOString()` onto the payload
- [`assets/js/utils.js`](../../assets/js/utils.js) — re-exports selected members of `window.LogosDx.Utils` (CDN-loaded `@logosdx/utils`) grouped by comment banner: error handling (`attempt`, `attemptSync`), flow control (`retry`, `circuitBreaker`, `withTimeout`, `composeFlow`, `rateLimit`, `RateLimitTokenBucket`, `batch`, `withInflightDedup`), data operations (`clone`, `equals`, `merge`, `reach`, `setDeep`, `setDeepMany`, `makeNestedConfig`, `castValuesToTypes`, enabled/disabled-value helpers), unit conversion/formatting (time and byte units, `parseTimeDuration`/`formatTimeDuration`, `parseByteSize`/`formatByteSize`), performance/caching (`memoize`, `memoizeSync`, `debounce`, `throttle`), validation/type guards (`assert`, `assertObject`, `isFunction`/`isObject`/etc.), error type classes (`RetryError`, `TimeoutError`, `CircuitBreakerError`, `RateLimitError`, `ThrottleError`, `AssertError` and matching `is*Error` guards), and misc (`wait`, `TimeoutPromise`)

## Coupling

- [`assets/js/editor.js`](../../assets/js/editor.js) imports `cvData`, `defaultMessage`, `CVDataSchema` (cv-data domain) and `applyStyles`/`getCurrentStyles`/`resetStyles` (styles domain) directly — changes to the CV data schema or the styles API surface can break `applyChanges()`/`resetData()` here.
- [`assets/js/keyboard.js`](../../assets/js/keyboard.js) imports `getCurrentAiScreen` from [`assets/js/ai/ui.js`](../../assets/js/ai/ui.js) (ai-chat domain) — a rename of that export breaks keyboard shortcut gating for `Escape`, `⌘,`, and `⌘Enter`.
- [`assets/js/editor.js`](../../assets/js/editor.js) lazy-imports `./ai/ui.js` (`initializeAI`) when switching into `ai` mode, and `main.js` lazy-imports the same module for `window.applyCvFromAI` — both are dynamic `import()` calls, not static imports, so the ai-chat bundle only loads when needed.
- [`assets/js/exports.js`](../../assets/js/exports.js) (cv-data domain) imports `getEditorMode`/`getEditor` from [`assets/js/editor.js`](../../assets/js/editor.js) to sync the open editor after a CVML import.
- [`assets/js/toast.js`](../../assets/js/toast.js) and [`assets/js/modal.js`](../../assets/js/modal.js) import `parseMarkdown`/`renderDocMarkdown` from [`assets/js/markdown.js`](../../assets/js/markdown.js) (cv-data domain).

## Conventions worth knowing

- All local JS module imports use a `?v=VERSION` cache-busting query string; the version is declared as `VERSION` in [`assets/js/version.js`](../../assets/js/version.js) (currently `2026.03.27.1`), the `<script type="module">` tag in [`index.html`](../../index.html), and every `import ... from '...js?v=...'` statement — all three must be bumped together on any JS change.
- Cross-module communication goes through `on()`/`emit()` from `observable.js`, not direct function imports, for anything that isn't a tight data dependency (e.g. `cv:save`, `cv:reset`, `editor:save`, `editor:full-screen`) — `toast.js` and `keyboard.js` are pure event-bus consumers with no imports of the modules that trigger their behavior.
- `keyboard.js` tracks repeated key presses with a `LastPressed`/`TimesPressed` module-level state pair and a `checkTimesPressed(key, times, interval)` helper, used to distinguish a single `⌘,`/`Escape` press from a double press within `KEYPRESS_INTERVAL` (500ms) or a custom window (1000ms for `⌘,`).
- `main.js` exposes editor/action-menu/modal/export functions on `window` because [`index.html`](../../index.html) wires them via inline `onclick="..."` attributes rather than addEventListener calls.
