# dev-tooling

## What it does

Repo-maintenance tooling, not app code: a cache-busting version bump script ([`scripts/bump-version.mjs`](../../scripts/bump-version.mjs)) and a Playwright/Chromium driver for running the app headlessly ([`.claude/skills/run-cv-generator/`](../../.claude/skills/run-cv-generator)), packaged as a Claude Code skill. [`package.json`](../../package.json)'s `bump`, `check-version`, and `shots:approval` scripts invoke these directly; `start` runs the human-path equivalent of what the driver spawns programmatically. There is no test framework in the repo — `driver.mjs smoke` is the only automated check that exists, and it is run manually after touching [`assets/js/`](../../assets/js).

## Artifacts

- [`.claude/skills/run-cv-generator/SKILL.md`](../../.claude/skills/run-cv-generator/SKILL.md) — Claude Code skill definition (`name`/`description` frontmatter plus body) documenting prerequisites (`pnpm install`, `npx playwright install chromium`, `brew install poppler`), the agent-run command surface (`smoke`, `shot`, `screenshots`, `print`, `sizes`, `repl`, `repl.sh`), the human-run path (`node_modules/.bin/http-server` / `pnpm start`), REPL command reference, CLI flags, and a Gotchas/Troubleshooting section

## CLI code

- [`scripts/bump-version.mjs`](../../scripts/bump-version.mjs) — dependency-free Node script; `collectFiles()` walks every `.js` under [`assets/js/`](../../assets/js) plus [`index.html`](../../index.html); `currentVersion()` reads the `VERSION` literal out of [`assets/js/version.js`](../../assets/js/version.js) via regex; `nextVersion()` auto-bumps to today's date with sequence 1, or increments the existing sequence if today is already stamped; `--check` reports every `?v=` reference that doesn't match `version.js`'s current value and exits 1 on drift; default (no arg, or an explicit `YYYY.MM.DD.N` argument) rewrites every `?v=...` query string across the collected files to the new version, then updates the `VERSION` literal in `version.js`
- [`.claude/skills/run-cv-generator/driver.mjs`](../../.claude/skills/run-cv-generator/driver.mjs) — Playwright Chromium automation; dispatches on `argv[0]` to one of `smoke` (16 assertions covering default render, JS/CSS edit+apply, markdown parsing, localStorage persistence, Zod rejection, print pagination on base and custom CSS, AI tab, help modal, CVML export, fullscreen toggle, reload persistence), `repl` (stdin command loop), `shot` (single screenshot), `print` (paginated PDF + per-page PNGs for a given CV/CSS/CVML combination), `sizes` (reads `getComputedStyle().fontSize` screen vs. print for a fixed set of selectors), `approval-states` (renders the human-in-the-loop approval dialog templates in each state without a live LLM), and `screenshots`/`docshots` (regenerates the README hero [`screenshot.png`](../../screenshot.png) plus candidate doc shots); `startServer()` spawns `node_modules/.bin/http-server` on an ephemeral port (or reuses `--url`) and polls until it answers; `installRouting()` disk-caches every cross-origin GET under `tmp/cv-cdn-cache/` keyed by `sha1(url)` and aborts requests matching `googletagmanager|google-analytics|analytics\.google|doubleclick`; `open()` waits on a `READY` predicate (`window.applyChanges` is a function, `window.monaco.editor.getEditors().length > 0`, `#name` has text) rather than `DOMContentLoaded`, retrying up to 3 times against jsdelivr stalls; an `addInitScript` seeds `localStorage['cv-first-visit'] = 'true'` and a `page.on('dialog', accept)` handler auto-accepts `confirm()`; `parseCvml()` uses the same two regexes as `exports.js` to load real `.cvml` exports; `capturePrint()` calls `page.pdf({ preferCSSPageSize: true })` with no `margin` option (so `print.css`'s `@page { margin: 0.4in }` is not overridden) then rasterizes with `pdftoppm`, falling back to a single continuous paper-width screenshot if `pdftoppm` is absent
- [`.claude/skills/run-cv-generator/repl.sh`](../../.claude/skills/run-cv-generator/repl.sh) — bash wrapper keeping `driver.mjs repl` alive across separate shell invocations via a named pipe (`tmp/run-repl/cmd`) plus a `sleep 86400 > "$FIFO"` holder process, since closing the pipe's write end would send EOF and exit the REPL; subcommands `start`/`send`/`log`/`stop`; `send` tracks a byte offset in `tmp/run-repl/offset` and prints only output appended to `tmp/run-repl/out.log` since the previous `send`
- [`.claude/skills/run-cv-generator/example-cv.js`](../../.claude/skills/run-cv-generator/example-cv.js) — fixture CV data object (Grace Hopper) in the same shape the JavaScript editor tab expects (ends in `return {...}`), consumed via the REPL's `cv <file>` command or the driver's `--cv` flag
- [`.claude/skills/run-cv-generator/example-styles.css`](../../.claude/skills/run-cv-generator/example-styles.css) — fixture CSS (accent color override on the header and section headings) consumed via the driver's `--css` flag; applied as an override layer on top of [`index.html`](../../index.html)'s existing `base.css`/`cv.css`/`print.css` links, not a replacement

## Coupling

- [`scripts/bump-version.mjs`](../../scripts/bump-version.mjs) rewrites the `VERSION` constant in [`assets/js/version.js`](../../assets/js/version.js) and every `?v=` import query string across `assets/js/**` and [`index.html`](../../index.html) (editor-shell domain) — any new or renamed `.js` file under [`assets/js/`](../../assets/js) is picked up automatically by `collectFiles()`'s directory walk, but its imports still need a `?v=` query string for the bump to normalize.
- [`package.json`](../../package.json)'s `bump`/`check-version` scripts invoke [`scripts/bump-version.mjs`](../../scripts/bump-version.mjs) directly; `shots:approval` invokes `driver.mjs approval-states`; `start` (`http-server ./ -c-1 -o`) runs the same binary and `-c-1` no-cache flag that `driver.mjs`'s `startServer()` spawns programmatically, minus the driver's CDN disk-caching and readiness polling.
- `driver.mjs`'s `approvalStates()` and `docShots()` dynamically `import()` [`/assets/js/ai/templates.js`](../../assets/js/ai/templates.js) (ai-chat domain) to render `approvalDialog`/`approvalRecord`/`errorBubble` markup against production CSS — `approvalStates()` uses all three exports, but `docShots()` only calls `approvalDialog()`, so renaming `errorBubble` or `approvalRecord` only breaks `approvalStates()`, not `docShots()`.
- `driver.mjs` reads `window.applyChanges`, `window.setEditorMode`, `window.monaco`, `window.exportCV`, `window.resetData`, `window.showHelpModal`, `window.closeModal`, and `window.toggleFullscreen` (editor-shell/cv-data domains) — renaming any of these breaks the driver's `READY` predicate or the corresponding REPL command. The first seven are explicit `window.<name> = <fn>` assignments in `main.js`; `window.monaco` is not app-assigned — it's created by the Monaco AMD loader in `editor.js` (`require(['vs/editor/editor.main'], ...)`) once it resolves from jsdelivr.
- `driver.mjs`'s `parseCvml()` duplicates the two regexes `exports.js` (cv-data domain) uses to parse the `.cvml` format — a change to that format requires updating both places.
- [`package.json`](../../package.json)'s `devDependencies` (`http-server`, `playwright`) are the only two npm packages installed locally in the repo; every other dependency the app itself uses loads from a CDN.

## Conventions worth knowing

- `bump-version.mjs` normalizes every `?v=` reference it finds on a bump, not only ones matching the previously-known-current string, so a stale hand-edited pin self-heals rather than being silently skipped.
- Version format is `YYYY.MM.DD.N`; an argument-less bump increments `N` only when today's date already matches the current stamp in `version.js`, otherwise it resets to `1`.
- `driver.mjs` must be run as `node .claude/skills/run-cv-generator/driver.mjs <command>` from the repo root — it resolves `playwright` from `node_modules/`, so it fails with `ERR_MODULE_NOT_FOUND` if copied outside the repo.
- Driver output (screenshots, PDFs, rasterized print pages) lands in `tmp/run-shots/` (gitignored), except the hero image at repo-root [`screenshot.png`](../../screenshot.png), which the `screenshots`/`docshots` command overwrites directly because [`README.md`](../../README.md) references that exact path.
- `--no-cdn-cache` bypasses `driver.mjs`'s disk cache and is discouraged outside of deliberately testing CDN behavior — the app hard-blocks on Monaco resolving from jsdelivr, and a cold uncached load was measured at up to ~49s (with roughly 1-in-4 cold loads not completing within 15s).
- Local JS edits are visible to the driver without a version bump (`http-server -c-1` sends no-cache and every driver run gets a fresh browser profile); the `?v=` bump remains required for the deployed GitHub Pages site, just not for driving local changes through `driver.mjs`.
